# Claude Code 권한 설정

## 적용 범위

개인 기본 권한은 `~/.claude/settings.json`의 `permissions`에서 관리한다. 이 저장소의 [권한 템플릿](../config/claude-permissions.json)은 병합할 규칙의 원본이며, 파일을 저장소에 두는 것만으로 적용되지는 않는다. 기존 테마와 다른 설정을 보존하고 `allow`·`ask` 목록에 중복 없이 추가한다.

`../scripts/setup.sh`를 실행하면 이 병합을 자동으로 수행한다. 기존 설정 항목과 이미 있는 규칙은 그대로 두고 템플릿에만 있는 규칙만 추가하며, 변경이 있을 때만 원본을 `settings.json.bak.<시각>`으로 백업한다. 직접 병합하려면 아래 표를 참고해 수동으로 편집한다.

현재 템플릿의 공통 Python 경로는 `/home/jiho` 환경 기준이다. 다른 컴퓨터에서는 실제 설치 경로에 맞게 조정한다.

## 이번 단계의 규칙

| 구분 | 명령 | 목적 |
| --- | --- | --- |
| 허용 | 템플릿에 열거한 `git status` 명령 | 작업 상태 확인 |
| 허용 | `git diff --stat`, `git diff --check` | 변경 규모와 공백 오류 확인 |
| 허용 | 공통 Python 버전, pypdf 설치 정보, pip 의존성 검사 | 기존 도구 재사용 확인 |
| 승인 요청 | `git add`, `git commit`, `git push` | Codex가 담당하는 Git 변경 작업 확인 |

`allow`는 일치하는 호출의 수동 승인을 생략하고, `ask`는 일치하는 호출에 승인을 요청한다. 규칙 우선순위는 `deny`, `ask`, `allow` 순서다. 이 설정은 완전한 허용 명령 목록이 아니며, 나머지 호출에는 Claude의 기본 권한 처리와 다른 유효 설정이 적용된다.

명령 규칙은 호출 문자열을 기준으로 한다. 예를 들어 `git push` 규칙만으로 `git -C <경로> push`나 다른 프로그램을 통한 동일 작업까지 통제한다고 가정하지 않는다. Claude의 역할 지침과 필요한 범위의 도구 허용을 함께 사용한다.

Python 전체 실행, 패키지 설치, 파일 편집, 모든 테스트 명령을 일괄 허용하지 않는다. 프로젝트별 테스트는 실제 명령을 확인한 뒤 해당 프로젝트 설정에 필요한 범위로 추가한다.

## 적용 확인

Claude Code의 새 세션에서 `/permissions`를 열어 사용자 범위의 규칙을 확인한다. `git status --short`와 공통 Python의 `-m pip check`로 조회·검증 동작을 확인할 수 있다. 승인을 시험하려고 실제 커밋이나 푸시를 실행할 필요는 없다.

Codex가 Claude를 비대화형으로 호출할 때에는 승인 요청을 직접 처리할 수 없는 경우 호출이 거부될 수 있다. `git add`·`commit`·`push`는 CLAUDE.md에 따라 Codex가 위임한 작업에서 Claude가 애초에 호출하지 않는 명령이므로, 이 `ask` 규칙은 자동화를 막는 제약이 아니라 실수로 호출하는 경우를 막는 안전장치로 유지한다. 그 밖의 명령에서 승인 요청이 거부되면 필요한 명령과 실패 이유를 Codex에 반환하고, 자동으로 권한 범위를 넓히지 않는다.
